# Бот «Тип привязанности»

Telegram-бот с тестом на тип привязанности. Сразу после теста он показывает тип, а полную расшифровку открывает после подписки на канал сексолога [@vanillapropsy](https://t.me/vanillapropsy).

**Стек:** Python 3.12, aiogram 3, SQLite, Docker Compose. Режим long polling, поэтому домен и SSL не нужны.

## Как работает

1. `/start` → приветствие Даши и меню:
   - «🧠 Узнать свой тип привязанности» — тест;
   - «💌 Онлайн-запись к сексологу» — запись на созвон (если `BOOKING_OWNER_ID` пуст — ссылка в личку `CONTACT`);
   - «👀 Кто такая Дарья?» — рассказ о Даше с кнопками «Онлайн-запись», «🖤 Отзывы» (картинка `content/media/reviews.jpg`) и «Подписаться на канал».

   Если тест не начат за `DIARY_DELAY_MINUTES` минут — бот один раз присылает дневник самопознания (PDF).
2. «Узнать свой тип привязанности» → описание теста и шкала 1–5 → 10 вопросов. Вопросы идут в одном сообщении, которое редактируется, есть кнопка «Назад».
3. После последнего ответа бот проверяет подписку на канал:
   - **подписан** → сразу полный результат;
   - **не подписан** → тип, шкалы и гейт с кнопками «Подписаться» и «Я подписался(ась)».
4. Полный результат: картинка типа, расшифровка («В сексе», «Точка роста», «Важно помнить») с кнопками «Поделиться тестом», «Пройти ещё раз» и «Подписаться на канал». Через `CTA_DELAY_MINUTES` минут после прохождения теста приходит сообщение «Пиши «близость»» с кнопками записи, лички Даши (`CONTACT`) и подписки на канал. Кнопка подписки есть и после заявки на созвон, и в сообщении о её подтверждении.
5. Тем, кто увидел гейт, но не подписался, через `REMINDER_HOURS` часов приходит **одно** напоминание.

Команды: `/start`, `/result` (показать последний результат), `/book` (запись на созвон), `/stats` (только для `ADMIN_IDS`), `/schedule` и `/bookings` (для Даши и админов).

Админам (`ADMIN_IDS`) после `/start` бот показывает постоянную кнопку «📊 Статистика» под полем ввода, под самой статистикой — кнопка «🔄 Обновить». Если кнопку скрыли — `/admin` вернёт её.

## Запись на созвон

Включается переменной `BOOKING_OWNER_ID` (Telegram ID Даши). Без неё кнопок записи нет.

**Клиент.** Кнопка «📅 Записаться на консультацию» есть в финальном сообщении после теста, плюс команда `/book`. Дальше: формат (пробная встреча 15 минут или консультация 60 минут) → день → время → «Записаться». Время клиент всегда видит по Москве.

- Записаться можно на месяц вперёд, но не ближе чем за 2 часа до начала.
- Пробная встреча доступна один раз. Если пробную отклонили, она истекла или её отменили, она не считается использованной.
- У одного человека может быть одна будущая запись каждого формата.
- Отменить запись клиент может не позже чем за 30 минут до начала, через `/book`. Позже только через Дашу.
- Клиенту приходят напоминания за сутки и за час до подтверждённой встречи. Ссылку на звонок Даша присылает сама.

**Даша** работает по своему времени (Бангкок).

- Новая заявка приходит ей сообщением с кнопками «Подтвердить» и «Отклонить». Слот держится 24 часа, но не дольше начала встречи. Если за это время Даша не ответила, слот освобождается, а клиент получает предложение выбрать другое время.
- `/schedule` задаёт недельное расписание (нажать день и прислать `10:00-19:00`, `10:00-14:00, 16:00-20:00` или `выходной`) и особые даты: отпуск или другие часы на конкретный день. Пока расписание не задано, свободных окон нет.
- `/bookings` показывает предстоящие записи. Там же можно подтвердить, отклонить или отменить запись; клиент получит уведомление.

Между записями всегда есть минимум час. Двойная запись исключена на уровне базы: время разбито на 15-минутные ячейки с первичным ключом, запись занимает ячейки звонка и часа после него. Если двое нажали одновременно, вторая вставка падает и откатывается целиком, а клиент видит «это время только что заняли». Правила (горизонт, 2 часа, 30 минут, час между записями, 24 часа на подтверждение) собраны вверху `bot/booking.py`.

Как устроен тест и что изменено по сравнению с исходной версией — в [docs/test-methodology.md](docs/test-methodology.md).

## Структура

```
bot/
  __main__.py      точка входа (python -m bot)
  config.py        настройки из переменных окружения
  content.py       загрузка вопросов и текстов из YAML
  scoring.py       подсчёт баллов (чистые функции)
  handlers.py      сценарий бота
  ui.py            экраны и клавиатуры
  subscription.py  проверка подписки на канал
  reminders.py     напоминания
  delivery.py      отправка результата с картинкой и дневника
  db.py            SQLite: пользователи, прохождения, события, записи
  booking.py       запись на созвон: правила, расписание, слоты (чистые функции)
  booking_ui.py    экраны и клавиатуры записи
  booking_handlers.py  запись: клиент, решения и расписание Даши, истечение брони, напоминания
content/
  quiz.yaml        вопросы, шкалы, порог
  texts.yaml       все тексты бота
  media/           картинки типов (secure/anxious/avoidant/disorganized.jpg), reviews.jpg и diary.pdf
tests/             pytest
```

## Подготовка в Telegram

1. В [@BotFather](https://t.me/BotFather): `/newbot` → получить токен. Там же задать имя «Твой Тип Привязанности» (`/setname`), описание (`/setdescription`) и аватар (`/setuserpic`).
2. **Добавить бота администратором канала** @vanillapropsy. Права можно снять все, нужен только сам статус админа. Без этого Telegram не отдаёт боту статус подписчиков, и проверка подписки работать не будет (при старте бот пишет об этом предупреждение в лог).
3. Узнать свой Telegram ID (например, у [@userinfobot](https://t.me/userinfobot)) для доступа к `/stats`.
4. Для записи на созвон: узнать Telegram ID Даши, вписать его в `BOOKING_OWNER_ID`. Даша должна один раз нажать `/start` у бота, иначе Telegram не даст боту ей написать. После этого Даша задаёт расписание через `/schedule`.

## Деплой на VPS

Хватит самого маленького сервера (1 vCPU, 512 МБ–1 ГБ RAM) с Ubuntu/Debian.

```bash
# 1. Docker
curl -fsSL https://get.docker.com | sh

# 2. Код
git clone https://github.com/Menanshin/tg_bot_daria_vanila.git
cd tg_bot_daria_vanila

# 3. Секреты (в git не попадают)
cp .env.example .env
nano .env          # BOT_TOKEN, ADMIN_IDS
chmod 600 .env

# 4. Папка для базы (контейнер работает от uid 1000, не от root)
mkdir -p data && sudo chown 1000:1000 data

# 5. Запуск
docker compose up -d --build
docker compose logs -f
```

### Обновление

```bash
git pull && docker compose up -d --build
```

### Правка текстов без пересборки

`content/` смонтирован в контейнер, поэтому достаточно:

```bash
nano content/texts.yaml
docker compose restart
```

Если в YAML ошибка, бот не стартует и пишет причину в `docker compose logs`. Перед перезапуском на проде лучше прогнать тесты (см. ниже): они ловят пропущенные ключи, незакрытые HTML-теги и слишком длинные сообщения.

### Бэкап базы

```bash
sqlite3 data/bot.db ".backup 'backup-$(date +%F).db'"
```

## Метки источников (deep links)

Чтобы понимать, откуда приходят люди, давай в каждом месте свою ссылку:

```
https://t.me/<имя_бота>?start=insta_bio
https://t.me/<имя_бота>?start=reels_oct
https://t.me/<имя_бота>?start=channel_pin
```

Метка: латиница, цифры, `_` и `-`, до 64 символов. Бот запоминает метку при первом заходе пользователя, и в `/stats` видно, какой источник сколько привёл. Ссылки «Поделиться» помечаются как `share`.

## Данные и приватность

В базе хранятся Telegram ID, username, метка источника, ответы на тест и результат, а для записи на созвон ещё формат и время встречи. Ответы касаются отношений, поэтому:

- `data/` и `.env` не попадают в git;
- база не должна покидать сервер, бэкапы храни в надёжном месте;
- если аудитория из РФ или ЕС, нужна политика конфиденциальности (152-ФЗ / GDPR); ссылку на неё стоит добавить в описание бота в BotFather.

## Разработка

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements-dev.txt
ruff check .
pytest -q
```

Для локального запуска нужен отдельный тестовый бот и тестовый канал: `cp .env.example .env`, заполнить, затем `python -m bot`.

CI (GitHub Actions) на каждый push прогоняет ruff, pytest и сборку Docker-образа.
